# Nevados mobile

The Expo app: onboarding over an animated Nevado scene, then a chat that answers from the curated park knowledge on the phone. Expo SDK 58, React Native 0.88 (new architecture, Hermes), TypeScript strict, Expo Router. Target: Android arm64. How answers are picked: [`../docs/architecture.md`](../docs/architecture.md).

## Prerequisites

| Tool | Version in use | Notes |
|---|---|---|
| Node | 22 (fnm) | npm is the only package manager |
| JDK | OpenJDK 21 | Gradle |
| Android SDK | `~/Android/Sdk` (set in `android/local.properties`) | needs `ndk;27.1.12297006` and `platforms;android-37` |
| adb | system | install, side-load, `adb reverse` |

`android/` is generated by Expo (Continuous Native Generation) and ignored by git. Never edit it; configure native behavior in `app.json` or config plugins, then `npx expo prebuild`.

## Build and run

```bash
npm install                      # also runs scripts/patch-ort.js (onnxruntime-react-native fix)
npx expo prebuild --platform android   # fresh clone only: generates android/ (set ANDROID_HOME or android/local.properties sdk.dir)
cd android
./gradlew assembleDebug   -PreactNativeArchitectures=arm64-v8a   # dev client, ~3-10 min first time
./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a   # standalone, signed with the debug key
```

| APK | Path | Starts |
|---|---|---|
| debug | `android/app/build/outputs/apk/debug/app-debug.apk` | the expo-dev-client launcher; needs Metro (`npx expo start`, then `adb reverse tcp:8081 tcp:8081`) |
| release | `android/app/build/outputs/apk/release/app-release.apk` | straight into the app, JS bundled |

Install with `adb install -r <apk>`. Expo Go cannot run this app (native modules: llama.rn, onnxruntime, Skia).

Model files are not in the APK. Side-load them into a debug install:

```bash
scripts/push-knowledge.sh              # e5 GGUF + vectors + scorer named in assets/data/knowledge/index.json
scripts/push-knowledge.sh --with-laya  # also the Laya ONNX and tokenizer (only if policy.laya.enabled)
```

The script uses `run-as`, so it needs a debuggable build. A release APK installed over a debug install keeps the files.

## Onboarding scene

One JSON document (`SceneDoc`, `src/onboarding/scene/`) describes layers, objects, palette and a timeline keyed by progress (0 = screen 1, 2 = screen 3). Native draws it on one Skia canvas; web (Lab, `/design`) draws it with react-native-svg. The SVG renderer is the reference, so a new body kind goes into both `NevadoScene.tsx` and `skia/drawScene.ts`.

- Transitions: "Siguiente", the dots and a swipe animate progress (`transitionMs` 900, ease-out). Layer blur is keyed per screen (`layer.<id>.blur`); on Skia it is drawn at half resolution.
- Idle motions (drift, bob, sway, breathe, rise, live) run on wall-clock time and stop under the OS reduce-motion setting.
- The Pet lives on the `ruizMascot` layer, hosted on the volcano's crater; its emotion is keyed per screen.
- The Lab (`npx expo start --web`, then `/lab`) autosaves to `localStorage`, which hides later `preset.ts` changes: use "Preset" to reload, "Copiar JSON" to hand edits back.

Perf baseline on the reference phone (Galaxy A24, release, `adb shell dumpsys gfxinfo`): ~10 ms per frame at rest and in the chat, transitions with p90 30-46 ms. Measure on a release build: debuggable builds run native code much slower.

## Checks

```bash
npm run typecheck     # tsc --noEmit
npx expo lint         # add --no-cache if import/no-unresolved reports a stale path
npm test              # Jest (jest-expo), Node only
```

Format touched files with `npx prettier --single-quote --print-width 100 --write <files>` (no repo-wide Prettier config). Jest cannot load Skia (ESM): keep scene and layout data modules free of renderer imports.

## Known limits

- `BubblesLab.test.tsx` fails: its fixture copies a catalog answer that the curation changed.
- `valid_until` on knowledge entries is not enforced.
- Hermes support for `String.prototype.normalize` and `Intl` is unverified, so text folding uses explicit maps.

## Identificar imágenes sin internet

Toca la cámara a la izquierda del cuadro del chat. En la app nativa puedes tomar una foto o abrir la galería. En la vista web de Metro se abre el selector de archivos y la clasificación corre en el navegador con WebAssembly. Metro sirve el codificador y WebAssembly desde el mismo origen; el navegador procesa la foto seleccionada localmente. MobileNetV3 y ONNX Runtime convierten el recorte central de la foto en un vector de 1024 dimensiones. La app compara ese vector por coseno con el índice incluido. Si las mejores clases quedan demasiado cerca o la similitud es baja, pide otra toma. La coincidencia es orientativa, especialmente entre paisajes parecidos.

Las categorías de la guía son frailejón, Laguna del Otún, piedra pómez, chivito de páramo y cóndor andino. Cada etiqueta se convierte en una consulta de texto plano, por ejemplo `dime que es esto chivito de páramo`, y se vincula con una respuesta del catálogo. La categoría persona activa una frase de bienvenida al adjuntar una foto y escribir «¿Qué ves aquí?» o «Mírame». La detección es de categoría y no distingue identidades. Antes de enviar puedes ver la foto, quitarla o escribir una pregunta. El chat muestra la foto y el texto tal como lo escribiste. La etiqueta visual se añade solo a la consulta interna. Las fotos enviadas se mantienen durante la conversación en memoria. El selector del sistema puede crear archivos temporales.

El paquete incluye `assets/vision/encoder.onnx`, los vectores y sus etiquetas. Las imágenes de referencia se procesan fuera de `mobile/`. Sus fichas de origen están en [vision-sources.json](scripts/vision-sources.json). El modelo deriva de [MobileNetV3 Small publicado por ONNX Community](https://huggingface.co/onnx-community/mobilenetv3_small_100.lamb_in1k), cortado antes de la capa de clasificación ImageNet.

Para regenerar los vectores, organiza las fotos en una carpeta externa con un subdirectorio por ID de `assets/vision/classes.json`. Usa referencias independientes y variadas. La carpeta opcional `other` contiene ejemplos parecidos que deben favorecer la abstención. Descarga el `onnx/model.onnx` original del enlace anterior. Con NumPy, Pillow, ONNX y ONNX Runtime instalados en Python, ejecuta desde `mobile/`:

```powershell
py scripts/build-vision.py C:/ruta/model.onnx C:/ruta/fotos
```

La cámara requiere reinstalar una compilación nativa porque incorpora `expo-image-picker`. Prueba la compilación instalada en modo avión, sin Metro.
