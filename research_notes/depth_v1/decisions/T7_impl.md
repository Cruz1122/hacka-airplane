## Design choices
- Depth ships as a separate asset `depth.json`: `{entries: {id: {l0:[{text,atoms}], layers:[{kind,texts}], walk, complements:[fid], rotation?:[l0 idx]}}}`.
- When the three input files are absent: no `depth.json` (a stale one is unlinked) and the `continuation` key is omitted from `policy.json` (absent = null in the type). Not emitted as `"continuation": null` because that would change `policy.json`, and the brief requires `git diff mobile/assets` empty.
- Cue: whole message, `foldText`-folded, ≤6 words, regex `^LEAD CORE TAIL$`. "¿sigue abierto?", "más o menos cuánto" and "más cerca de Pereira" do not match. `why_cue` is a bare "por qué" (R4.5): it is served only when an unserved `why` layer exists, otherwise it takes the normal path.
- Continuation turns: no embed, no retrieval, `prevText` and `prevScores` untouched. Urgent messages never take this branch.
- State `{anchor id, served "id\0fid", layers served, walk served}`. A new answered entry starts a fresh state, and the same entry re-asked keeps it. Urgent, abstain, empty message and `resetContext` clear it (R4.7). The no_state and exhausted texts do not clear it.
- "sigue" (R7.4): among unserved layers, pick the one whose best text carries the most unserved complement fids (tie: seeded RNG). It must add ≥1 new fid, otherwise move to the walk. Entries with an empty `complements` list serve their layers in order. Within the layer, the paraphrase is chosen by rotation among the ones with maximal gain. Walk: next unserved id, its L0 (rotation), prefixed by a bridge (rotation over `bridges`). Exhausted: `texts.exhausted` + `texts.related` with `{topics}` = first 2 walk labels (extra optional key `related`; the brief only listed no_state/exhausted).
- Rotation (R6.5): per key `id:L0`, `id:L<n>` and `bridges`, seeded Fisher-Yates cycles. On wrap it reshuffles so the head differs from the last served. It never serves the same index twice in a row, even through a filter. It lives for the engine's life and `resetContext` keeps it. The first answer of an entry with depth also comes from the rotation, so the canonical text leaves the rotation (R7.6) when the data omits it.
- Emergency (R6.6): the rotation set is `rotation`; with fewer than 3 approved the canonical `short` is served. Urgent turns use it too. The 123 banner text stays catalog `short`.
- `new KnowledgeEngine(assets, vectors, embed, reranker?, score?, {seed})`. The seed is injectable (R7.7).
- Reply types unchanged: depth and walk replies are `answer` (entry title/sources, no steps). no_state and exhausted are `abstain` with the policy text.

## Review fixes (2026-11-24)

The Sonnet fix task hit the Claude rate limit before editing. The orchestrator applied the four
findings from `reviews/T7_logic.md` and `reviews/T7_safety.md`:

- An `emergency_direct` entry does not serve a depth layer on "sigue" or "por qué". "sigue" may
  still walk; "por qué" falls through to retrieval.
- `policy.continuation == null` returns before depth validation, so a bad depth block is ignored.
- Every L0 and layer atom must be in that entry's `complements`.
- A layer text that repeats a served complement is eligible only when the layer has no fully new text.
